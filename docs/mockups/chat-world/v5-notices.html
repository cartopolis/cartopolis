Cartopolis chat — v5 addendum: notices from the municipality

Yes: a notice is a point with four extra things: which objects it's about (this tree, this stretch of road, this building, identified by their register numbers), when, a status that moves from planned to done, and an official author. It's posted to the places it touches, so the people who follow those places hear about it, and the objects themselves carry it in the 3D world.

1Attached to things, not just a spot

Cartopolis already knows the city object by object: BAG buildings, BGT trees, lampposts and road surfaces, each by its official number. A notice names them, so the actual tree gets a ring and the actual road gets hatching.

2It goes where people already listen

No separate app or subscription. A notice about the Turfsingel is posted to Turfsingel, Binnenstad and Groningen, the same place communities residents already follow, and out to the fediverse.

3One notice, updated in place

Planned → underway → done. Updates attach to the notice instead of arriving as new, disconnected posts, and when it's done the marks disappear from the world.

FWhen it's done, the world has changed

  • The hatching and the fence disappear by themselves, and the bench stays as an ordinary object.
  • The felled tree disappears when the BGT stops listing it. The notice keeps a record of where it stood.
  • The notice stays in the place's history, so "what happened here?" has an answer later.

Three kinds of object a notice can point at

KindIts numberDoes the app already have that number?
Buildings (BAG)The BAG identificatie, nationalYes. Every drawn building carries it; the building card is built on it.
Street objects (BGT)The BGT lokaal_id, nationalNo. Atlas reads it while extracting, but only to drop duplicates. The map files it writes have a tree's position, not its number. See the first rule below.
Prims (built in Cartopolis)The prim's id, a URL on this serverYes, on the wire. The id only means something on this server, so it's written as a web address for anyone outside.
  • Every reference carries a snapshot: kind, position or outline, name. The app draws the ring or hatching from the snapshot, so BGT numbers don't have to be added to the map files at all. It also keeps working after the object is gone, which for a felled tree is the whole point.
  • Hiding or replacing a specific BGT object (the tree disappearing the day it's felled, before the BGT catches up) does need the number in the map files. That's a change to atlas's extractor and the client's reader in the same commit, and it makes the files bigger. Leave it until it's needed.
  • Prims a notice brings are grouped by one column on the prim, the way content packs are grouped today by prims.origin. Deleting the notice deletes its prims, and nobody can edit them except the notice's author.
  • Pointing at somebody's prim is fine: a notice only marks it, it never changes it. Only official notices draw marks in the world; an ordinary point that mentions a prim just links to it.
  • Possible later: a scripted prim reacting to the notice's status (a detour sign that lights up while underway), through the message channels scripts already listen on.

The format: a point with a notice section

The same ActivityStreams object as every other point, with one extension. An app that doesn't know the extension still shows a sensible post with a picture, a place and dates.

What it builds on, and what it leaves out

  • Builds on the place communities from the previous addendum: a notice is a post addressed to the places it touches, worked out from its objects.
  • Builds on the registers Cartopolis already reads: BAG buildings by their identificatie, BGT trees, lampposts, road surfaces and boundaries. The objects in a notice are the same ones drawn on the map.
  • Official accounts are organisation accounts marked official by the operator. This is the one place where the server vouching for someone is exactly right: the notices are public, not private messages.
  • Could be filled from day one by importing what municipalities already publish: official announcements carry a location, so a place could show them before its municipality ever signs up. An option, not a requirement.
  • Leaves out formal objections (a legal procedure, linked to rather than rebuilt), and reports from residents about broken things (the other direction, a separate use case).
  • Possible later, because the pieces exist: the router avoiding a closed road, and a notice carrying a 3D model of what's planned, using the existing IFC building import, so residents can walk around it before it's built.
