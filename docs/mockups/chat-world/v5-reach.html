Cartopolis chat — v5 addendum: who can read it

Every chat, and so every point, has one of three reaches, and the app always shows which: private (end-to-end encrypted), public in Cartopolis, or a public post on the fediverse through ActivityPub, later. A point is stored as an ActivityPub object from day one, so the same point can go into an encrypted chat now and into a public post later without being redesigned.

Private

Direct messages and private groups
  • End-to-end encrypted: the server passes messages on and stores them, but can't read them.
  • Points, their pictures and shared real locations only ever go here.
  • Never federated. ActivityPub direct messages aren't encrypted, so they stay out of this list.

Public in Cartopolis

Here (nearby), Global, public rooms
  • Not encrypted. The server decides who hears a nearby message by where they stand.
  • Avatars, voice and emotes live here too, run by the simulator as today.
  • Not federated. None of this is real-time-capable over ActivityPub, and it shouldn't be.

Public post later

The fediverse: Mastodon, Pixelfed and others
  • A point posted publicly as @you@cartopolis.org. Anyone can see it, follow you and reply.
  • Posts from people you follow that carry a location show up on the map.
  • Only a point you choose to post. Never your real location, never automatically.

CThe fediverse on the map later

  • A Following map layer (it goes in the existing Layers menu): posts with a location from people you follow, including people on Mastodon or Pixelfed, pinned where they were posted.
  • A post from outside has no camera view, so Look here uses a default angle over the spot.
  • Replies go back out as ordinary fediverse replies.

A point, stored as an ActivityPub object from day one

The same object is the encrypted payload of a private message now, and the body of a public post later. Only the Cartopolis-specific camera view is an extension; everything else is standard ActivityStreams, which already has Place with latitude and longitude.

{
  "type": "Note",
  "content": "Show at the Stadsschouwburg on Saturday?",
  "location": {
    "type": "Place",
    "name": "Stadsschouwburg, Turfsingel 86",
    "latitude": 53.2166, "longitude": 6.5708
  },
  "attachment": [{ "type": "Image", "url": "…/view.jpg" }],
  "url": "https://cartopolis.org/go?place=53.2166,6.5708,120m,-35,40",
  "cartopolis:view": { "altitude": 120, "pitch": -35, "heading": 40 }
}
// private: this whole object is encrypted, and the image is an encrypted
// attachment whose key travels inside it. public: it is sent as-is.

Decide now, so ActivityPub is cheap later

  1. Store points as ActivityStreams objects, as on the left. Converting a home-made format later means converting every stored point, and encrypted ones can only be converted on the phones.
  2. Fix the address: @name@cartopolis.org. Moving a fediverse account to another domain breaks followers' links, so choose the domain before anyone federates. Usernames of deleted accounts are never reused.
  3. Every chat carries its reach (private, public in Cartopolis, public post) as data, not as a label drawn in one screen. The marks in A read from it.
  4. Nothing real-time goes over ActivityPub. Avatars, voice, nearby chat and location sharing stay on the simulator's own connection. ActivityPub delivers posts in seconds, over HTTP, and that's what it's for.
  5. Private chats never become fediverse direct messages, which aren't encrypted. If encrypted chat across servers is wanted one day, there is work in the W3C Social Web group on carrying the same encryption (MLS) over ActivityPub; the design leaves room for it but doesn't depend on it.
  6. Moderation grows a remote side: blocking whole servers, and passing reports to the server a post came from (ActivityPub has a Flag activity for this). Today's report path is where it hooks in.
